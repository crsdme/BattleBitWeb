# Жизненный цикл и ввод

Эта глава — жизненный цикл именно игрока BBGodot: какие функции тут уже написаны и в каком порядке они крутят движение. Полная цепочка от создания ноды до `queue_free()`, пауза, приоритеты и карта на TypeScript — в `04b_жизненный_цикл_полностью.md`.

Godot сам вызывает функции с подчёркиванием. Ты их не зовёшь. Ты заполняешь их телом, и движок приходит в нужный момент.

Порядок для игрока в этом проекте:

```
1. Дерево player.tscn собрано, дети существуют.
2. _ready() у каждой ноды, снизу вверх по дереву: сначала дети, потом родители.
3. Каждый кадр отрисовки: _process(delta)        — анимации, IK, перезарядка
4. Каждый шаг физики:    _physics_process(delta) — гравитация, ходьба, прыжок
5. Когда пришло событие мыши или клавиши: _unhandled_input(event)
```

`delta` — секунды с прошлого вызова. Умножение скорости на `delta` делает движение одинаковым и при 60, и при 144 кадрах.

## _ready

Запуск один раз. Здесь кэш нод уже заполнен (`@onready` отработал до входа в `_ready`).

`player_controller.gd`:

```gdscript
func _ready() -> void:
    _ensure_actions()
    Input.mouse_mode = Input.MOUSE_MODE_CAPTURED
```

Создать действия, если их ещё нет, и спрятать курсор.

`player_animation.gd`:

```gdscript
func _ready() -> void:
    _arm(_body_animation, LOOPING_BODY, _on_body_finished)
    _arm(_hands_animation, LOOPING_HANDS, _on_hands_finished)
    _play_body("idle")
    _play_hands("fps_equip")
    _hands_oneshot = "fps_equip"
```

Включить цикл нужным клипам, подписаться на конец анимации, поставить тело в idle, проиграть доставание оружия один раз.

`view_model.gd` в `_ready` выставляет масштаб и поворот из `@export`, запоминает позу покоя винтовки, строит IK и выключает тени у мешей рук и оружия. Тени от модели, которая приклеена к камере, грязнят картинку. Мировое тело солдата тени кастует как обычно.

`body_local_visibility.gd` в `_ready` один раз перестраивает меш. Каждый кадр это делать не нужно: голова не вырастает заново.

## _physics_process — только движение

Физика игрока целиком в `player_controller.gd`. Остальные скрипты в физический шаг не лезут.

Порядок внутри кадра важен, его стоит запомнить как шаблон любого персонажа:

```gdscript
func _physics_process(delta: float) -> void:
    var was_on_floor := is_on_floor()
    # 1. гравитация или прыжок — ДО move_and_slide
    # 2. горизонтальная скорость
    # 3. move_and_slide() — здесь обновляется is_on_floor()
    # 4. сравнение was_on_floor с новым is_on_floor(): взлёт и приземление
    # 5. сказать другим системам, что произошло
```

`is_on_floor()` до `move_and_slide()` — это пол предыдущего шага. После вызова — пол текущего. Поэтому «только что приземлился» пишется так:

```gdscript
if was_on_floor and not is_on_floor():
    _in_air = true
if _in_air and is_on_floor():
    animation.notify_landed()
    _in_air = false
```

Флаг `_in_air` отделяет шаг с края от настоящего падения. `notify_landed()` зовётся один раз, в кадр касания.

Гравитация берётся из настроек проекта, а не зашивается числом:

```gdscript
var gravity: float = ProjectSettings.get_setting("physics/3d/default_gravity")
velocity.y -= gravity * delta
```

Прыжок записывает вертикальную скорость напрямую: `velocity.y = JUMP_VELOCITY`. Пока персонаж в воздухе, эта скорость каждый кадр уменьшается на `gravity * delta`, и он описывает дугу.

Горизонталь сглаживается, а не ставится мгновенно:

```gdscript
velocity.x = move_toward(velocity.x, target.x, ACCELERATION * delta)
velocity.z = move_toward(velocity.z, target.z, ACCELERATION * delta)
```

`move_toward(текущее, цель, максимум_за_кадр)` — официальная функция Godot. При `ACCELERATION = 28` и `SPEED = 4.8` разгон до полной скорости занимает примерно 0.17 секунды. Отпускание клавиш так же плавно гасит скорость, потому что цель становится нулём.

`move_and_slide()` применяет `velocity`, сталкивается с `StaticBody3D` и сам обнуляет скорость в стену. После него `velocity` уже изменён движком. Читать скорость для анимации нужно после этого вызова, что код и делает:

```gdscript
var horizontal_speed := Vector2(velocity.x, velocity.z).length()
animation.update_view(horizontal_speed, animate_grounded, velocity.y)
```

## _process — то, что рисуется

`view_model.gd` и `fps_arm_ik.gd` работают в `_process`, потому что они двигают картинку, а не физическое тело.

Порядок двух `_process` задан приоритетом:

```gdscript
# view_model._ready
set_process_priority(10)

# после создания IK
_ik.set_process_priority(20)
```

Меньшее число выполняется раньше. Сначала вьюмодель двигает винтовку и цель левой руки. Потом IK читает уже новую позицию цели и ставит кости. Если приоритеты перепутать, руки будут догонять оружие с опозданием в один кадр.

Пока идёт перезарядка, `_follow_arm_sway()` не вызывается. Позу винтовки в эти секунды пишет `_pose_weapon`. Два писателя одной `weapon.transform` в одном кадре не работают.

## _unhandled_input — мышь

```gdscript
func _unhandled_input(event: InputEvent) -> void:
    if event is InputEventMouseMotion and Input.mouse_mode == Input.MOUSE_MODE_CAPTURED:
        rotate_y(-event.relative.x * MOUSE_SENSITIVITY)
        head.rotate_x(-event.relative.y * MOUSE_SENSITIVITY)
        head.rotation.x = clampf(head.rotation.x, deg_to_rad(-PITCH_LIMIT), deg_to_rad(PITCH_LIMIT))
```

`_unhandled_input` приходит, если UI не забрал событие. Для взгляда это правильный канал: когда появится меню, клики по кнопкам не будут крутить камеру.

`event.relative` — сдвиг мыши в пикселях за событие, не позиция курсора. Минус нужен, чтобы движение мыши вверх поднимало взгляд.

`rotate_y` крутит всё тело. `head.rotate_x` крутит только узел головы. `clampf` обрезает угол, чтобы шея не провернулась назад.

`ui_cancel` — это Escape, действие есть в Godot сразу. По нему курсор отпускается. Левый клик, пока курсор виден, захватывает его обратно.

## Как заводятся свои действия

```gdscript
func _bind_key(action: String, keycode: Key) -> void:
    if not InputMap.has_action(action):
        InputMap.add_action(action)
    for existing in InputMap.action_get_events(action):
        if existing is InputEventKey and existing.physical_keycode == keycode:
            return
    var event := InputEventKey.new()
    event.physical_keycode = keycode
    InputMap.action_add_event(action, event)
```

Функция безопасна при повторном заходе в сцену: действие не дублируется, та же клавиша не вешается второй раз.

`physical_keycode` смотрит на физическую клавишу, а не на букву в текущей раскладке. W остаётся W и в русской раскладке (там на этой клавише Ц). Для движения берут `physical_keycode`.

Сейчас привязано:

| Действие | Клавиша | Где читается |
| --- | --- | --- |
| `move_forward` | W | `Input.get_vector` |
| `move_back` | S | `Input.get_vector` |
| `move_left` | A | `Input.get_vector` |
| `move_right` | D | `Input.get_vector` |
| `jump` | Space | `is_action_just_pressed` |
| `reload` | R | `is_action_just_pressed` |
| `ui_cancel` | Escape | встроено в Godot |

## Что в какой функции писать

| Вопрос | Куда |
| --- | --- |
| Это столкновение, гравитация, скорость тела? | `_physics_process` |
| Это кость, оружие у камеры, таймер визуала? | `_process` |
| Это разовый ответ на клик или движение мыши? | `_unhandled_input` |
| Это найти ноды, включить циклы, спрятать меш? | `_ready` |
| Это число, которое дизайнер крутит на ноде? | `@export` |
| Это закон, одинаковый для всех экземпляров? | `const` |

Один скрипт может иметь и `_process`, и `_physics_process`. В этом проекте они разведены по файлам специально: у контроллера нет `_process`, у вьюмодели нет `_physics_process`. По файлу сразу видно, в каком тике он живёт.
