# Сцены и ноды

Сцена — это дерево нод, сохранённое в `.tscn`. Нода — объект с типом, именем, трансформом и, по желанию, одним скриптом.

Скрипт не «является игроком». Скрипт висит на ноде и получает её возможности через `extends`.

`player_controller.gd` начинается с `extends CharacterBody3D`. Пока этот файл висит на ноде типа `CharacterBody3D`, в нём работают `velocity`, `is_on_floor()`, `move_and_slide()`. Повесишь его на обычный `Node` — этих методов не будет, проект не запустится.

## Дерево player.tscn

```
Player                    CharacterBody3D     player_controller.gd
├── CollisionShape3D      капсула радиус 0.38, высота 1.85, центр на y = 0.925
├── Body                  Node3D              body_local_visibility.gd
│   └── Soldier           экземпляр body-rigged-animated.glb, масштаб 155
├── BodyAnimation         пустой AnimationPlayer, скрипты его не используют
├── Head                  Node3D, поднят на y = 1.7
│   └── Camera3D          current = true, near 0.02
│       └── ViewModel     Node3D              view_model.gd
│           ├── Hands     экземпляр fps-hands-rigged-animated.glb
│           └── Weapon    экземпляр M4A1_with_grips.glb
├── ViewAnimation         пустой AnimationPlayer, скрипты его не используют
└── Animation             Node                player_animation.gd
```

`ArmIK` в файле сцены нет. `view_model.gd` создаёт его в `_ready()` через `add_child`. Поэтому в редакторе до запуска игры этой ноды не видно, а в запущенной сцене она есть.

Пустые `BodyAnimation` и `ViewAnimation` сейчас ни на что не влияют. Клипы лежат внутри импортированных glb, на их собственных `AnimationPlayer`. Скрипт анимации ходит туда по пути:

```
$"../Body/Soldier/AnimationPlayer"
$"../Head/Camera3D/ViewModel/Hands/AnimationPlayer"
```

## Зачем тело и голова разделены

`Player` крутится по горизонтали (yaw). `Head` крутится по вертикали (pitch) и зажат в пределах ±85°.

Ходьба считает направление от `transform.basis` тела, а не от камеры. Взгляд вверх не наклоняет вектор движения. Это стандартная сборка FPS: тело отвечает за «куда иду», голова — за «куда смотрю».

`Body` повёрнут на 180° по Y (`Transform3D(-1, 0, 0, 0, 1, 0, 0, 0, -1, ...)`). Модель солдата из Blender смотрит не туда, куда смотрит `CharacterBody3D`. Поворот на ноде `Body` выравнивает модель, не трогая физику и не трогая файл glb.

Камера стоит на высоте 1.7 м. Капсула высотой 1.85 с центром 0.925 стоит ногами на нуле родителя. Пол в карте имеет верх на y = 0, игрок поставлен на y = 0.2, чтобы на старте не застрять внутри коллайдера пола.

## Масштаб моделей

Солдат в сцене умножен на 155. Руки в `view_model.gd` умножаются на `hands_scale` (380) и ещё на `viewmodel_scale` (0.2). Винтовка умножается на 0.24.

Так бывает, когда glb приехали из разных единиц (метры, сантиметры, «как удобно в Blender»). Масштаб живёт в одном месте — на ноде или в `@export` — и исходный файл не пересохраняют под игру.

`Camera3D.near = 0.02`, потому что руки находятся очень близко к камере. При ближней плоскости 0.05 их бы обрезало.

## Дерево test_map.tscn

```
TestMap                 Node3D, скрипта нет
├── WorldEnvironment    небо и тонмап
├── Sun                 направленный свет, тени включены
├── Fill                слабый заполняющий свет, energy 0.25
├── Floor               StaticBody3D
│   ├── Mesh            коробка 60×1×60, сдвинута на y = -0.5
│   └── Collision       такая же коробка, тот же сдвиг
├── CrateA / B / C / Tall    StaticBody3D, у каждого Mesh + Collision
└── Player              экземпляр player.tscn
```

У карты нет скрипта. Это правильно для тестового уровня: она только расставляет свет, пол и игрока.

## Mesh и Collision — две разные вещи

Красивая коробка (`MeshInstance3D`) ничего не сталкивает. Невидимая форма (`CollisionShape3D` на `StaticBody3D` или `CharacterBody3D`) ничего не рисует.

У пола и у каждого ящика есть оба. Если убрать `Collision` у ящика, игрок пройдёт сквозь картинку. Если убрать `Mesh`, останется невидимая стена.

`StaticBody3D` не двигается от физики. Его ставят на пол, стены, ящики. `CharacterBody3D` двигаешь ты, через `velocity` и `move_and_slide()`. Его ставят на игрока и на управляемых персонажей.

## Как карта получает игрока

В `test_map.tscn`:

```
[ext_resource type="PackedScene" path="res://scenes/player/player.tscn" id="1_player"]

[node name="Player" parent="." instance=ExtResource("1_player")]
```

Это экземпляр, не копия файла. Правка `player.tscn` меняет игрока на всех картах. Сдвиг `transform` на экземпляре в карте двигает только этого игрока на этой карте.

В редакторе это делается так: перетащи `player.tscn` из FileSystem на ноду карты. Godot сам запишет `instance`.

## Типы нод, которые уже используются

| Тип | Роль в этом проекте |
| --- | --- |
| `Node` | Логика без позиции. `Animation`. |
| `Node3D` | Позиция в 3D без физики. `Head`, `Body`, `ViewModel`. |
| `CharacterBody3D` | Тело, которое скрипт двигает сам. Корень игрока. |
| `StaticBody3D` | Неподвижный коллайдер. Пол и ящики. |
| `CollisionShape3D` | Форма столкновения. Без неё тело не сталкивается. |
| `MeshInstance3D` | Отрисованная сетка. |
| `Camera3D` | Точка взгляда. `current = true` делает её активной. |
| `AnimationPlayer` | Проигрывает клипы, которые приехали внутри glb. |
| `Skeleton3D` | Кости внутри импортированной модели. IK пишет в них позы. |
| `Marker3D` | Пустая точка в пространстве. Полюса локтей и цель перезарядки. |
| `WorldEnvironment` | Небо и постобработка на всю сцену. |
| `DirectionalLight3D` | Солнце. |

Один скрипт вешают на одну ноду. Второму скрипту нужна вторая нода. Поэтому видимость висит на `Body`, анимация — на `Animation`, контроллер — на корне. Они соседи в одном дереве и находят друг друга путями, а не слиты в один файл.
