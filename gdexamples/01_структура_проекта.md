# Структура проекта

Godot-проект — это папка, в которой лежит `project.godot`. Всё, что игра загружает, адресуется от этой папки через путь `res://`.

`res://scripts/player/player_controller.gd` означает файл
`BBGodot/scripts/player/player_controller.gd`.

## Что лежит в BBGodot

```
BBGodot/
  project.godot          настройки проекта. Это не скрипт.
  icon.svg               иконка в списке проектов
  scenes/
    maps/test_map.tscn   уровень, с которого игра стартует
    player/player.tscn   сборка игрока: физика, камера, модели, скрипты
  scripts/
    player/*.gd          логика. Сцена на них ссылается.
  assets/
    player/*.glb         модели тела и рук
    weapons/*.glb        модель винтовки
  .godot/                кэш редактора. Игра его не читает как контент.
  gdexamples/            этот гайд. В игру не входит.
```

Папки `scenes`, `scripts`, `assets` — договорённость команды, а не требование движка. Godot видит только пути `res://`. Имена папок нужны людям.

Для этого проекта договорённость такая:

- `scenes/` — то, что собираешь в редакторе и ставишь в мир.
- `scripts/` — поведение. Внутри папка по фиче: `player/`.
- `assets/` — привезённые модели, текстуры, звуки. Их почти не правят кодом.

Когда фич станет много, внутри каждой из этих папок появляется ещё один уровень: `weapons`, `ui`, `ai`. Корень проекта при этом остаётся коротким.

## project.godot

Файл текстовый, но его правят через Project → Project Settings. Руками его открывают, чтобы понять, что уже включено.

Сейчас в нём важно вот это:

| Строка | Значение |
| --- | --- |
| `run/main_scene` | `res://scenes/maps/test_map.tscn` — сцена, которая открывается по F5 |
| `config/features` | Godot 4.7, рендер Forward Plus |
| `3d/physics_engine` | Jolt Physics |
| `rendering_device/driver.windows` | d3d12 |
| `window/stretch/mode` | `canvas_items`, aspect `expand` — окно тянется без чёрных полос |

Главная сцена — всегда карта или меню, а не сам игрок. Игрока карта вставляет как экземпляр. Тогда того же `player.tscn` можно поставить на другую карту без копирования скриптов.

Input Map в `project.godot` сейчас пустой. Клавиши W A S D, прыжок и перезарядка создаются кодом в `player_controller.gd`, функция `_ensure_actions()`. Для прототипа это удобно: проект запускается на любой машине без ручной настройки. Для большой игры действия заводят в Project → Input Map, а в коде остаётся только `Input.is_action_pressed("jump")`.

## Файлы, которые не являются игрой

| Файл | Что это |
| --- | --- |
| `*.gd` | Скрипт. Его пишешь ты. |
| `*.tscn` | Сцена: дерево нод и ссылки на скрипты. Её собираешь в редакторе. |
| `*.glb` | Модель из Blender. В сцену её ставят как экземпляр. |
| `*.import` | Как Godot импортировал модель или текстуру. Создаётся сам при первом открытии. |
| `*.uid` | Постоянный id скрипта. Godot 4 пишет его сам. Не переименовывай содержимое. |
| `.godot/` | Кэш, раскладка редактора, импортированные копии. Можно удалить: Godot пересоберёт при открытии проекта. |
| `assets/player/create_fps_hands.py` | Скрипт для Blender, не для Godot. Он один раз собирает блок-руки и экспортирует glb. В игре не выполняется. |

Импортированный glb в сцене выглядит как обычное дерево нод: меш, скелет, `AnimationPlayer`. Исходный `.glb` при этом не меняется. Всё, что игра делает с моделью в рантайме (спрятать голову, повернуть клип в цикл), живёт в скрипте.

## Как сцена находит скрипт

В начале `player.tscn` есть строки `ext_resource`. Это список деталей:

```
[ext_resource type="Script" path="res://scripts/player/player_controller.gd" id="1_controller"]
[ext_resource type="PackedScene" path="res://assets/player/body-rigged-animated.glb" id="3_body"]
```

Дальше у ноды написано `script = ExtResource("1_controller")`. Значит, на эту ноду повешен этот скрипт. У ноды `Soldier` написано `instance=ExtResource("3_body")`: внутрь вставлен целый glb, а не пустая нода.

Если переименовать скрипт в проводнике Windows, ссылка в `.tscn` сломается. Переименовывай через FileSystem-док Godot: он поправит пути сам.

## Куда класть новый файл

Задай себе один вопрос: это данные мира, поведение или привезённый ассет?

- Поведение игрока → `scripts/player/имя_работы.gd`
- Сборка, которую ставят в мир → `scenes/player/` или `scenes/weapons/`
- Картинка, звук, glb → `assets/...`

Имя файла — `snake_case`, как `player_controller.gd`. Имя ноды в сцене — `PascalCase`, как `ViewModel`. Имя функции — `snake_case`, как `start_reload`.
