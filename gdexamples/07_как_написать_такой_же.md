# Как написать такой же код с пустого проекта

Ниже порядок, в котором собирают этого игрока. Каждый шаг заканчивается тем, что игра запускается. Следующий шаг добавляет одну работу, а не «всё сразу».

Открывай Godot 4, рендер Forward Plus. Физику можно включить Jolt в Project Settings → Physics → 3D, как в этом проекте. Это не влияет на то, как пишутся скрипты.

## Шаг 1. Карта без игрока

Сцена `scenes/maps/test_map.tscn`, корень `Node3D`.

1. `WorldEnvironment`, в Environment добавь Sky → ProceduralSky.
2. `DirectionalLight3D`, включи тень.
3. Пол: нода `StaticBody3D`.
   - ребёнок `MeshInstance3D`, mesh = Box, size `(60, 1, 60)`, position y = `-0.5`
   - ребёнок `CollisionShape3D`, shape = BoxShape того же размера и того же сдвига

Сохрани сцену. Project → Project Settings → Application → Run → Main Scene → эта карта. F6 запускает текущую сцену, F5 — главную.

Пол без `CollisionShape3D` выглядит готовым и не держит игрока. Меш и форма — пара.

## Шаг 2. Тело, которое ходит

Новая сцена `scenes/player/player.tscn`. Корень обязан быть `CharacterBody3D`, имя `Player`. На `Node3D` метода `move_and_slide` нет.

Добавь ребёнка `CollisionShape3D`, форма Capsule, radius `0.38`, height `1.85`. Подними форму так, чтобы низ капсулы стоял на y = 0 родителя. В этом проекте форма сдвинута на y = `0.925`.

Повесь на корень скрипт `scripts/player/player_controller.gd`. Минимальное движение, с которого начинают, выглядит так:

```gdscript
extends CharacterBody3D

const SPEED := 4.8
const ACCELERATION := 28.0
const JUMP_VELOCITY := 4.6

func _ready() -> void:
    _ensure_actions()

func _physics_process(delta: float) -> void:
    var gravity: float = ProjectSettings.get_setting("physics/3d/default_gravity")
    if not is_on_floor():
        velocity.y -= gravity * delta
    elif Input.is_action_just_pressed("jump"):
        velocity.y = JUMP_VELOCITY

    var input_dir := Input.get_vector("move_left", "move_right", "move_forward", "move_back")
    var direction := (transform.basis * Vector3(input_dir.x, 0.0, input_dir.y)).normalized()
    var target := direction * SPEED
    velocity.x = move_toward(velocity.x, target.x, ACCELERATION * delta)
    velocity.z = move_toward(velocity.z, target.z, ACCELERATION * delta)
    move_and_slide()

func _ensure_actions() -> void:
    _bind_key("move_forward", KEY_W)
    _bind_key("move_back", KEY_S)
    _bind_key("move_left", KEY_A)
    _bind_key("move_right", KEY_D)
    _bind_key("jump", KEY_SPACE)

func _bind_key(action: String, keycode: Key) -> void:
    if not InputMap.has_action(action):
        InputMap.add_action(action)
    var event := InputEventKey.new()
    event.physical_keycode = keycode
    InputMap.action_add_event(action, event)
```

Перетащи `player.tscn` на карту, подними его на y = `0.2`, запусти. Капсула невидима. Включи у корня видимость коллайдера в меню Debug, чтобы видеть тело. Стрелками его не двигают: движение сидит на действиях, не на `ui_up`.

`normalized()` после умножения на basis нужен обязательно. Без него диагональ быстрее прямого шага.

## Шаг 3. Взгляд

В сцену игрока добавь `Head` типа `Node3D`, position y = `1.7`. Её ребёнок — `Camera3D`, включи Current, Near поставь `0.02`.

В контроллер:

```gdscript
const MOUSE_SENSITIVITY := 0.0022
const PITCH_LIMIT := 85.0

@onready var head: Node3D = $Head

func _ready() -> void:
    _ensure_actions()
    Input.mouse_mode = Input.MOUSE_MODE_CAPTURED

func _unhandled_input(event: InputEvent) -> void:
    if event is InputEventMouseMotion and Input.mouse_mode == Input.MOUSE_MODE_CAPTURED:
        rotate_y(-event.relative.x * MOUSE_SENSITIVITY)
        head.rotate_x(-event.relative.y * MOUSE_SENSITIVITY)
        head.rotation.x = clampf(
            head.rotation.x,
            deg_to_rad(-PITCH_LIMIT),
            deg_to_rad(PITCH_LIMIT)
        )
```

`rotate_y` вызван на самом персонаже, поэтому влево-вправо крутится тело, и шаг WASD уже идёт туда, куда повёрнут корпус. `rotate_x` вызван только у `Head`, поэтому взгляд вверх не наклоняет направление бега.

Проверка: зайди в игру, посмотри вверх, нажми W. Персонаж должен идти по полу вперёд, а не взлетать вдоль взгляда.

## Шаг 4. Модель тела отдельной нодой

Кинь `body-rigged-animated.glb` в `assets/player/`. Godot сам сделает `.import`.

В сцену игрока добавь `Body` типа `Node3D`. На неё перетащи glb, получится ребёнок `Soldier`. Если модель смотрит назад, поверни `Body` на 180° по Y. Если модель крошечная, масштаб ставь на `Soldier` (в этом проекте 155), а не на корень `Player`. Масштаб корня портит скорость: `SPEED` задан в метрах физического тела.

Внутри экземпляра открой дерево и найди `AnimationPlayer`. Запомни имена клипов. Код ниже ждёт `idle`, `walk`, `jump`, `land`, `fall`. Имена должны совпасть с glb символ в символ.

Анимацию пока не пиши внутрь контроллера. Заведи ноду `Animation` типа `Node` и скрипт `player_animation.gd`.

Минимум, с которого начинают, до прыжков и перезарядки:

```gdscript
extends Node

@onready var _body_animation: AnimationPlayer = $"../Body/Soldier/AnimationPlayer"

var _body_clip := ""

func _ready() -> void:
    if _body_animation.has_animation("idle"):
        _body_animation.get_animation("idle").loop_mode = Animation.LOOP_LINEAR
    if _body_animation.has_animation("walk"):
        _body_animation.get_animation("walk").loop_mode = Animation.LOOP_LINEAR
    _play("idle")

func update_view(horizontal_speed: float, on_floor: bool) -> void:
    if not on_floor:
        return
    if horizontal_speed > 0.15:
        _play("walk")
    else:
        _play("idle")

func _play(clip_name: String) -> void:
    if clip_name == _body_clip:
        return
    if not _body_animation.has_animation(clip_name):
        return
    _body_clip = clip_name
    _body_animation.play(clip_name, 0.12)
```

Контроллер после `move_and_slide` добавляет две строки:

```gdscript
@onready var animation: Node = $Animation

# в конце _physics_process
var horizontal_speed := Vector2(velocity.x, velocity.z).length()
animation.update_view(horizontal_speed, is_on_floor())
```

Смысл разреза: контроллер измеряет скорость, анимация называет клип. Когда клипов станет шесть, раздуется только второй файл.

Дальше в этот файл добавляют ровно то, что уже есть в проекте: списки `LOOPING_BODY`, одноразовые `jump` и `land`, сигнал `animation_finished`. Прыжок контроллер замечает сам и зовёт `animation.notify_jumped()` в тот же кадр, где записал `velocity.y = JUMP_VELOCITY`. Приземление замечает сравнением пола до и после `move_and_slide`. Этот порядок описан в `04_жизненный_цикл.md`.

## Шаг 5. Руки как ребёнок камеры

Перетащи `fps-hands-rigged-animated.glb` на `Camera3D`. Оберни его в ноду `ViewModel` типа `Node3D`, чтобы масштаб и скрипт жили на обёртке, а не на корне импорта. Импорт при повторном экспорте из Blender проще заменить, если скрипт висит на твоей ноде.

Руки окажутся в мире камеры: их не надо каждый кадр копировать к `camera.global_position`. Дерево делает это само.

Поворот и масштаб подгони в инспекторе. Когда числа устаканятся, перенеси их в `@export` и применяй в `_ready`, как `view_model.gd`. Тогда настройка хранится в скрипте явно, а сцена не обрастает случайными трансформациями, смысл которых забывается.

Клипы рук подключают вторым `AnimationPlayer` в `player_animation.gd`, тем же приёмом, что и тело. Общий принцип `_play`: не вызывать `play`, если этот клип уже текущий, и передавать короткий blend.

## Шаг 6. Оружие и точки хвата

В Blender на винтовке стоят пустые объекты с точными именами:

- `RightHandGrip`
- `LeftHandGrip`
- `MagazineGrip`
- `Magazine` — сам меш магазина, который будет выдвигаться

Экспорт glb. В Godot положи его ребёнком `ViewModel` рядом с руками, имя ноды `Weapon`.

Маркер — это контракт. Код ищет его через `find_child`, а не через длинный путь. Переименуешь маркер в Blender — обнови строку в `_setup_ik` и больше нигде.

Поза винтовки в кадре:

```gdscript
var weapon_basis := Basis(Vector3.UP, deg_to_rad(-90.0)).scaled(Vector3.ONE * 0.24)
weapon.transform = Transform3D(weapon_basis, Vector3(-0.02, -0.18, -0.22))
```

Сначала добейся, чтобы ствол смотрел вперёд и сидел в кадре. IK подключают после этого. Иначе ты будешь чинить математику рук, хотя оружие просто повёрнуто боком.

## Шаг 7. IK отдельным скриптом

`fps_arm_ik.gd` пишут так, будто винтовки не существует. Функция `add_chain(имена костей, цель, полюс)` и функция `_process`, которая эти цепи решает.

Проверка без перезарядки:

1. Создай скрипт, добавь одну правую цепь, цель — `RightHandGrip`.
2. Полюс поставь сбоку-снизу от плеча (`Marker3D`).
3. Запусти. Кисть должна сесть на маркер, локоть наружу.
4. Добавь левую цепь.
5. Только потом пиши перезарядку.

Полюс двигают маркером, формулу `_elbow` не подкручивают «на глаз». Формула ставит локоть на правильное расстояние. Полюс выбирает, в какую сторону торчит сгиб.

`set_process_priority` у IK ставят выше, чем у скрипта, который двигает цель. Сначала новая позиция маркера, потом кости.

## Шаг 8. Перезарядка как таймер, не как клип

В этом проекте перезарядка процедурная: код двигает магазин и цель руки. Клип рук на это время выключают, иначе два хозяина пишут одни кости.

Каркас на вьюмодели:

```gdscript
var _reloading := false
var _reload_time := 0.0

func is_reloading() -> bool:
    return _reloading

func start_reload() -> bool:
    if _reloading:
        return false
    _reloading = true
    _reload_time = 0.0
    return true

func _process(delta: float) -> void:
    if not _reloading:
        return
    _reload_time += delta
    # по времени выставь hand_blend от 0 до 1 и обратно
    # сдвинь магазин
    # в конце _reloading = false
```

Контроллер по R вызывает `start_reload()` и не знает про фазы. Анимация спрашивает `is_reloading()` и останавливает свой `AnimationPlayer`.

Фазы режь константами с именами, как `REACH` и `PULL`. Магическое `if _reload_time > 0.34 and _reload_time < 0.76` через неделю не читается. Именованная граница читается.

`smoothstep` на каждой фазе ставь сразу. Линейное движение магазина потом всё равно придётся смягчать.

## Шаг 9. Скрыть голову локального тела

Когда камера окажется внутри солдата, повесь на `Body` скрипт видимости. Сначала попробуй простой путь: если голова — отдельный меш, сделай `visible = false`. К коду треугольников переходи только если модель одним куском, как `body-rigged-animated.glb`.

Списки костей копируй из арматуры Blender, не по памяти.

Чужое тело (будущий другой игрок) этот скрипт не получает. Скрипт висит на сцене локального игрока, и этим ограничивается.

## Как понять, что шаг закончен

После каждого шага в игре есть новое наблюдение:

| Шаг | Что должно быть видно |
| --- | --- |
| 1 | Пол, свет, небо |
| 2 | Невидимая капсула ходит и прыгает, не проваливается |
| 3 | Мышь крутит взгляд, W идёт туда, куда повёрнут корпус |
| 4 | Солдат переходит idle ↔ walk |
| 5 | Руки едут вместе с камерой |
| 6 | Винтовка сидит в кадре и смотрит вперёд |
| 7 | Ладони стоят на маркерах, локти не вывернуты |
| 8 | R увозит левую руку на магазин и возвращает |
| 9 | Снизу видны ноги и торс, головы перед камерой нет |

Если шаг не сошёлся, не пиши следующий. Почти каждая поломка в этой сборке — одно из четырёх:

- нет `CollisionShape3D`;
- скрипт повешен на ноду другого типа;
- имя клипа, кости или маркера не совпало с glb;
- два куска кода пишут одну и ту же позу в одном кадре.

## Как читают чужой скрипт в этом стиле

1. Строка `extends`. Какая нода это умеет.
2. Блок `const` и `@export`. Какие ручки у системы.
3. `@onready`. С кем скрипт говорит.
4. Публичные функции без подчёркивания. Это его наружный язык.
5. `_ready`, потом один `_process` или `_physics_process`. Что происходит за кадр.
6. Функции с подчёркиванием. Это внутренние шаги кадра.

Для `view_model.gd` наружный язык — две функции: `is_reloading` и `start_reload`. Всё остальное — как именно рука едет. Читать `_advance_reload` имеет смысл после того, как понял эти две.

Для `fps_arm_ik.gd` наружный язык — `add_chain` и `set_chain_target`. Формулу локтя читают, только когда локоть встал не туда.

Так же пиши свои файлы. Снаружи три-четыре метода с именами из игры. Внутри — детали, которые соседям не нужны.
