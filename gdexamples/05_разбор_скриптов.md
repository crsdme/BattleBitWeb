# Разбор каждого скрипта

Читай вместе с файлом. Смысл строк совпадает с текущим кодом.

## player_controller.gd — движение и команды

Файл: `scripts/player/player_controller.gd`. Нода: корень `Player`.

Делает три вещи: читает ввод, пишет `velocity`, сообщает соседям о прыжке, приземлении и перезарядке.

Не делает: не выбирает клип, не трогает кости, не двигает винтовку.

Связи:

```
Input  →  controller  →  animation.update_view / notify_jumped / notify_landed
                      →  view_model.start_reload()
```

Поля, которые имеет смысл помнить:

| Имя | Значение | Эффект |
| --- | --- | --- |
| `SPEED` | 4.8 | метры в секунду по горизонтали |
| `ACCELERATION` | 28 | насколько быстро скорость догоняет цель |
| `JUMP_VELOCITY` | 4.6 | стартовая скорость вверх |
| `MOUSE_SENSITIVITY` | 0.0022 | радианы на пиксель мыши |
| `PITCH_LIMIT` | 85 | градусы, дальше голова не задирается |

Наружу контроллер ничего не отдаёт. Он хозяин тела и сам вызывает чужие методы. Для одного игрока так и оставляют.

`animate_grounded` специально шире, чем `is_on_floor()`:

```gdscript
var animate_grounded := is_on_floor() or not _in_air
```

В кадр схода с края `_in_air` ещё false, и анимация остаётся наземной. Клип падения включится со следующего кадра, когда флаг уже поднят. Так шаг с бордюра не мигает кадром `fall`.

## player_animation.gd — какой клип играть

Файл: `scripts/player/player_animation.gd`. Нода: `Animation`.

Это диспетчер. У него нет своих клипов. Два `AnimationPlayer` уже сидят внутри glb.

Тело, клипы солдата:

| Условие | Клип |
| --- | --- |
| одноразовый `jump` или `land` ещё играет | ничего не переключать |
| не на полу | `fall` |
| скорость ≥ `run_speed_threshold` (6.5) | `run` |
| скорость > 0.15 | `walk` |
| иначе | `idle` |

Руки, клипы FPS:

| Условие | Клип |
| --- | --- |
| `view_model.is_reloading()` | остановить клип, руками владеет IK |
| играет одноразовый клип | не перебивать |
| в воздухе и `vertical_speed > 0.2` | `fps_jump` |
| в воздухе | `fps_fall` |
| скорость ≥ 6.5 | `fps_run` |
| скорость > 0.15 | `fps_walk` |
| иначе | `fps_idle` |

Важная цифра. `SPEED` в контроллере равен 4.8, порог бега равен 6.5. При текущих настройках `run` и `fps_run` не включаются: персонаж физически не разгоняется до порога. Клипы в списке `LOOPING_*` уже подготовлены. Чтобы бег появился, поднимают `SPEED` выше 6.5 или опускают `run_speed_threshold` ниже максимальной скорости. Порог вынесен в `@export`, его можно поменять в инспекторе у ноды `Animation`, не открывая скрипт.

Одноразовые клипы:

```gdscript
func notify_jumped() -> void:
    if not _view.is_reloading():
        _play_hands("fps_jump")
        _hands_oneshot = "fps_jump"
    _play_body("jump")
    _body_oneshot = "jump"
```

Пока `_body_oneshot` не пустой, `_update_body` выходит сразу. Когда `AnimationPlayer` доигрывает клип, сигнал вызывает `_on_body_finished`, строка очищается, и на следующем кадре снова выбирается idle или walk.

`_play_body` не перезапускает клип, если он уже играет:

```gdscript
if _body_animation == null or clip_name == _body_clip:
    return
_body_animation.play(clip_name, 0.12)
```

Второй аргумент `play` — длина перехода в секундах. 0.12 у тела и 0.1 у рук. Слишком большой blend смазывает прыжок. Слишком маленький даёт щелчок позы.

Перезарядка и клип рук взаимно исключают друг друга. IK каждый кадр ставит кости предплечья. Если в этот момент `AnimationPlayer` тоже пишет эти кости, они дерутся. Поэтому на время перезарядки проигрыватель рук останавливают.

Старт игры проигрывает `fps_equip` и записывает его в `_hands_oneshot`, чтобы ходьба не оборвала доставание.

Списки циклов — контракт с именами внутри glb. Добавляешь клип в Blender под новым именем — добавляешь строку в `LOOPING_BODY` или `LOOPING_HANDS` и ветку в `_update_body` или `_hands_clip_for`. Без строки в списке клип проиграется один раз и встанет на последнем кадре.

Клипы `sprint`, `crouch`, `fps_sprint`, `fps_ads_idle` в списках циклов есть, веток выбора для них нет. Это задел: имена уже зациклены, логика ещё не написана.

## view_model.gd — руки, винтовка, перезарядка

Файл: `scripts/player/view_model.gd`. Нода: `Head/Camera3D/ViewModel`.

Нода — ребёнок камеры, поэтому наследует и положение, и поворот взгляда. Отдельный код «приклеить оружие к камере» не нужен. Это делает дерево.

`_ready` применяет экспортные числа:

| Экспорт | Зачем крутить |
| --- | --- |
| `viewmodel_scale` 0.2 | общий размер рук и оружия в кадре |
| `hands_scale` 380 | подогнать единицы glb рук |
| `hands_pitch_degrees` 180 | развернуть модель, если она приехала спиной |
| `hands_offset` | сдвиг рук относительно камеры |
| `weapon_yaw_degrees` -90 | развернуть ствол вперёд |
| `weapon_scale` / `weapon_offset` | посадить винтовку в кадр |
| `left_grip` | с какой точки стартует левая ладонь: цевьё или магазин |

Меняй их в инспекторе на ноде `ViewModel`. Скрипт читает экспорты в `_ready`, так что новое число увидишь после перезапуска сцены.

### Покачивание оружия за руками

Клипы рук двигают кость `ArmsRoot`. Винтовка в этот скелет не входит, она соседняя нода. `_follow_arm_sway` читает, насколько `ArmsRoot` уехал от позы покоя, и прибавляет тот же сдвиг к винтовке. Руки остаются на маркерах хвата за счёт IK, оружие визуально качается вместе с клипом.

Поза покоя запоминается после `reset_bone_poses()`, до первого кадра анимации.

### IK собирается кодом

`_setup_ik` находит скелет и маркеры, создаёт `fps_arm_ik.gd`, добавляет две цепи:

```
UpperArm.R → Forearm.R → Hand.R    цель: RightHandGrip    полюс: справа-снизу
UpperArm.L → Forearm.L → Hand.L    цель: LeftHandGrip     полюс: слева-снизу
```

Полюс — точка, в сторону которой смотрит локоть. Без неё локоть в один кадр выворачивается вверх. Координаты полюса `(0.85, -0.85, -0.45)` и `(-0.85, -0.8, -0.5)` подбирают глазами: локоть должен торчать наружу и немного вниз.

`orientation` у обеих цепей сейчас `null`. Функция `_align_end` в IK умеет довернуть ладонь по базису маркера, но в этой сборке хватает направления кости к цели.

### Перезарядка — таймер из пяти фаз

`start_reload()` отказывает, если перезарядка уже идёт или IK не собрался. Возвращает `bool`, чтобы вызывающий мог узнать об отказе. Контроллер возвращаемое значение пока игнорирует: повторное R во время перезарядки просто ничего не делает.

Длительности в секундах:

| Фаза | const | Что видно |
| --- | --- | --- |
| REACH | 0.34 | рука едет с цевья на магазин, винтовка начинает заваливаться |
| PULL | 0.42 | магазин выезжает по `MAG_PULL`, завал доходит до максимума |
| HOLD | 0.35 | пауза с вынутым магазином |
| INSERT | 0.40 | магазин вставляется, винтовка выравнивается |
| RETURN | 0.34 | рука едет обратно на цевьё |

Сумма около 1.85 с. Чтобы сделать перезарядку быстрее, уменьшают эти `const`.

`_ease` — это `smoothstep`. Фаза начинается и заканчивается медленно, в середине быстрее.

`_pose_weapon(cant)` крутит винтовку вокруг локальной оси X до 10° и чуть сдвигает её. `cant` от 0 до 1.

`_pose_magazine(drop)` берёт позу покоя магазина, переводит её в мир через родителя и прибавляет сдвиг `MAG_PULL`, повернутый базисом вьюмодели. Сдвиг в локальных метрах вьюмодели, поэтому он едет вместе с камерой.

На время перезарядки цель левой цепи подменяется. В обычное время цель — нода `LeftHandGrip` на винтовке. В перезарядке цель — временный `Marker3D` по имени `LeftReloadTarget`, и его позицию каждый кадр ставят между цевьём и магазином:

```gdscript
_left_target.global_position = on_guard.lerp(on_mag, hand_blend)
```

`set_chain_target("Hand.L", _left_target)` переключает словарь цепи. Правая рука всё это время остаётся на `RightHandGrip`.

`_finish_reload` возвращает магазин и винтовку в запомненные трансформы и снова указывает левую цепь на цевьё.

## fps_arm_ik.gd — математика двух костей

Файл: `scripts/player/fps_arm_ik.gd`. Ноды в сцене до запуска нет, её создаёт вьюмодель.

Скрипт не знает слов «винтовка» и «перезарядка». Он знает цепь из трёх костей, цель и полюс. Его можно повесить на другого персонажа, если названия костей передать в `add_chain`.

Один кадр цепи:

1. Плечо и цель переводятся в пространство скелета.
2. `_elbow` ставит точку локтя законом косинусов: известны длина плеча, длина предплечья и расстояние до цели. Высота треугольника уходит в сторону полюса.
3. `_aim_bone` поворачивает кость так, чтобы её ребёнок смотрел в эту точку.
4. То же для предплечья: кисть смотрит в цель.
5. Если задан `orientation`, ладонь доворачивается по осям маркера.

Длины костей читаются из rest-позы один раз в `add_chain`, а не каждый кадр:

```gdscript
"upper_length": skeleton.get_bone_rest(middle).origin.length(),
"fore_length": skeleton.get_bone_rest(end).origin.length(),
```

Если цель дальше, чем сумма длин, расстояние зажимается чуть ближе полной растяжки. Рука тянется в струнку и не получает битое число из корня отрицательного значения. Если цель слишком близко, расстояние зажимается в разность длин. Локоть всегда существует.

После всех цепей вызывается `skeleton.force_update_all_bone_transforms()`. Без этого меш останется в позе прошлого кадра, хотя кости уже посчитаны.

Этот файл не настраивают числами в инспекторе. Его настраивают аргументами `add_chain`: имена костей, нода-цель, нода-полюс. Имена костей должны совпасть с glb. Полюс двигают, если локоть смотрит не туда.

## body_local_visibility.gd — локальное тело без головы

Файл: `scripts/player/body_local_visibility.gd`. Нода: `Body`.

Камера сидит внутри солдата. Голова и руки модели оказались бы перед объективом и внутри рук вьюмодели. Ноги, таз, торс и жилет должны остаться: игрок смотрит вниз и видит своё тело.

Скрипт сначала смотрит на имена мешей:

- в имени есть leg, thigh, boot, hip, torso, vest, chest — оставить
- в имени есть head, helmet, arm, hand — скрыть ноду и выключить её тень

`body-rigged-animated.glb` устроен иначе: это один меш на весь скелет, имя вроде `SubMesh_0`. Классификатор возвращает `unknown`. Тогда включается второй путь: копия меша, из которой выкинуты треугольники.

Какая вершина «голова или рука»: у вершины несколько весов костей, берётся кость с наибольшим весом. Если это `Head`, `Neck` или любая кость руки из списка `_ARM_BONES`, вершина скрытая.

Треугольник выкидывается, если скрыта хотя бы одна его вершина. На общем меше рука часто сидит треугольником, у которого два угла ещё на торсе. Порог «две скрытые вершины» оставил бы шипы вдоль плеча. Порог «одна» срезает шип. Комментарий в конце файла фиксирует именно это наблюдение.

Исходный glb не перезаписывается. `mesh_instance.mesh = stripped` подменяет меш только у этого экземпляра в запущенной игре. Другой солдат без этого скрипта останется целым. Поэтому скрипт висит на локальном `Body`, а не внутри общего glb.

Настройка под другую модель:

1. Если художник отдал голову отдельным мешем с именем `Head`, сработает первый путь, второй не нужен.
2. Если снова один меш, дополни списки `_HEAD_BONES` и `_ARM_BONES` точными именами костей из Blender. Имена чувствительны к регистру: `Head` и `head` — разные кости.

## create_fps_hands.py — не игровой код

Файл: `assets/player/create_fps_hands.py`.

Его открывают в Blender → Scripting → Run Script. Он строит арматуру из семи костей и кубы-сегменты, вешает веса 1.0 на свою кость и экспортирует `FPS_Hands.glb`.

В игре сейчас используется другой файл, `fps-hands-rigged-animated.glb`, уже с анимациями. Python-скрипт оставлен как генератор блок-рук, если понадобится заново выгрузить риг с теми же именами костей: `ArmsRoot`, `UpperArm.L`, `Forearm.L`, `Hand.L` и правая сторона.

Godot этот файл не исполняет.

## Как кадр проходит через все файлы

Один физический шаг, когда игрок идёт по полу и не перезаряжается:

```
_physics_process контроллера
    гравитация не пишется, потому что есть пол
    WASD → velocity
    move_and_slide
    animation.update_view(скорость, на полу, velocity.y)
        _update_body → play("walk") если клип сменился
        _play_hands("fps_walk") если клип сменился

_process вьюмодели, приоритет 10
    перезарядки нет → _follow_arm_sway сдвигает винтовку за ArmsRoot

_process IK, приоритет 20
    левая и правая цепи ставят ладони на маркеры хвата
```

Один шаг, когда только что нажали R:

```
контроллер: view_model.start_reload() → _reloading = true, цель левой руки подменена
animation.update_view видит is_reloading и останавливает AnimationPlayer рук
_process вьюмодели двигает фазы, магазин и LeftReloadTarget
_process IK тянет левую кисть в новую точку цели
```

Один шаг приземления:

```
до move_and_slide персонаж был в воздухе
после move_and_slide is_on_floor стало true
контроллер один раз зовёт animation.notify_landed()
тело играет "land", руки играют "fps_land"
пока oneshot не кончится, walk не перебивает клип
сигнал animation_finished очищает oneshot
```

## Что крутить, не ломая структуру

| Хочу | Куда |
| --- | --- |
| быстрее ходить | `SPEED` в контроллере |
| резче разгон | `ACCELERATION` |
| выше прыжок | `JUMP_VELOCITY` |
| чувствительность мыши | `MOUSE_SENSITIVITY` |
| чтобы walk сменился на run | поднять `SPEED` или опустить `run_speed_threshold` у ноды Animation |
| оружие выше или ниже в кадре | `weapon_offset` в инспекторе ViewModel |
| размер рук | `hands_scale`, `viewmodel_scale` |
| быстрее перезарядка | `REACH`, `PULL`, `HOLD`, `INSERT`, `RETURN` |
| локоть смотрит криво | вектор в вызове `_pole(...)` |
| другая кость считается головой | массивы в `body_local_visibility.gd` |
| рост капсулы | `CapsuleShape3D` в `player.tscn` и высоту ноды `Head` |
